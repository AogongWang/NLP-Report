## 2. 产品结构：一个实验平台，不是六个孤立页面

### 2.1 六个必做模块

| 编号 | 模块 | 必须覆盖的课程内容与交互 |
|---|---|---|
| M01 | 词向量调参可视化 | Word2Vec 的 CBOW / Skip-gram、GloVe；窗口、维度、负采样等适用参数；相似度、类比、二维投影、参数对照 |
| M02 | 序列模型分步模拟器 | RNN / LSTM / GRU；自定义序列、单步前向、隐状态、门控与细胞状态、回退、真实梯度传播观察 |
| M03 | Text-CNN 分类可视化 | 词向量矩阵、卷积滑动、激活、池化、分类概率；调整卷积核并观察中间值和输出 |
| M04 | 注意力机制交互面板 | 点积与加性注意力；源/目标序列、权重热力图、输入修改、掩码和加权输出 |
| M05 | 多模型对照工作台 | 朴素贝叶斯、线性 SVM、RNN、Text-CNN；同样本预测、分数/概率、批量指标、混淆矩阵和错误分析 |
| M06 | 损失与优化实验室 | 交叉熵、实际梯度更新、可调学习率、真实迭代曲线；可复现的慢收敛、震荡或发散案例 |

M01 同时实现三种算法入口，是本项目对 Word2Vec/GloVe 范围的全面覆盖决策。不得把 CBOW 换标题冒充 Skip-gram，也不得把共现散点图冒充 GloVe 训练。

共享入口包括：实验首页、六模块导航、数据集管理、实验记录、使用说明。不要做登录、付费、云端协作、排行榜或无关后台管理页面。

### 2.2 两种工作模式与一种展示视图

**原理模式：** 小规模、低维、可逐项核算。显示完整公式、矩阵维度和中间计算，支持单步、回退、重置。

**实验模式：** 较多数据、较大参数、批量训练/推理。计算放到 Worker，界面显示摘要、曲线和选中样本的详细轨迹。不能为了动画逐个播放全部样本。

两者使用同一套数学定义和兼容的参数格式，不得形成一套“演示算法”和另一套互不相干的真实算法。若使用加速后端，必须与透明参考实现进行数值一致性测试。

**演示视图：** 在上述真实实验基础上隐藏次要控件、放大主要图形与讲解文字，用于课堂汇报；不是播放录制视频，也不是展示预设假结果。

模式切换必须说明哪些维度、样本或历史被限制。不得无声丢弃数据或偷偷换模型。

## 3. 交互创新：至少完成以下四项

这些是本项目的交互设计创新，不要包装成未经证明的学术首创。

### I01. 计算显微镜：从一个数字追到它的来源

点击注意力格子、卷积激活、RNN 状态、损失点或分类分数，可以打开统一的“计算检查器”，显示：

```text
当前值 → 所属步骤 → 运算公式 → 输入数值 → 形状与索引 → 上游来源
```

图中选择、公式高亮、输入 Token 和矩阵单元联动。支持锁定检查器继续查看，不依赖一移开鼠标就消失的 Tooltip。

验收示例：点击一个 CNN 池化值，能定位到对应窗口和卷积核，并展示产生该值的真实计算。

### I02. 受控对照实验：只改一个因素，看到变化沿流程传播

支持将当前实验固定为 A，复制为 B，修改输入、掩码或参数，然后同步查看：

- 配置差异；
- 对应步骤的中间值差异；
- 共享坐标轴/色域下的结果；
- 差值热力图或曲线；
- 数据、初始化、随机种子、模型权重和预处理版本是否一致。

默认控制单一变量，但允许明确标注的多因素探索。改变学习率后重新训练，必须从同一初始检查点开始，不能用两个不同随机模型伪装受控实验。

这是模型内部的受控干预观察，不声称由此证明现实世界因果关系。

### I03. 跨模块实验链：样本与模型能够明确流转

实现至少两条完整链路：

```text
词向量快照 → 兼容的 RNN / CNN → 多模型评测
多模型错误样本 → 原模型单步解释 → 修改输入后的预测对比
```

点击“送入该模型解释”时，应带上真正参与预测的模型、分词结果、权重版本和样本，不得跳转后用随机参数解释另一个结果。

词表、维度、预处理或模型结构不兼容时，解释原因并提供重映射/重新初始化/重新训练选项；禁止静默替换。

### I04. 可复现的实验笔记

实验可以命名、固定为基线、保存、导入、导出和重新运行。

记录至少包含：输入、参数、数据来源/指纹、模型结构与权重标识、随机种子、预处理配置、算法版本、运行状态、实际结果和用户备注。

导出 JSON 用于复现，CSV 用于结果分析，Markdown 用于报告材料。大数据可选择“包含数据”或“仅引用数据”；后者必须说明重放时需要哪些原文件。**仅保存配置和种子不保证跨版本完全复现**，必要时连同权重和优化器状态保存。

补充加分功能：预设实验任务、先预测后验证、可导出的学习路径。它们排在六模块正确运行和上述四项之后，不得挤占核心开发。

## 4. 视觉设计：精致的科学实验工作台

### 4.1 视觉方向

采用“现代科学出版物 + 交互实验仪器”的风格：安静、清楚、精确，有足够留白，同时保持有效信息密度。

默认浅色主题。方向建议如下，具体颜色需实测对比度后调整：

```css
:root {
  --bg: #f5f7fa;
  --surface: #ffffff;
  --surface-muted: #edf2f7;
  --text: #172b3a;
  --text-secondary: #526477;
  --border: #d9e2eb;
  --accent: #087f8c;
  --accent-soft: #e3f4f5;
  --warning: #a45f00;
  --danger: #b42318;
  --radius-panel: 14px;
  --radius-control: 8px;
}
```

这是设计起点，不是“全部颜色已符合可访问性”的保证。图表色带单独管理，不把状态色随意拿来表示数值。

要求：

- 正文以 15–16px 为主，说明与数据标签仍须清晰；不能靠把字号压到 10px 来塞下复杂界面。
- 使用本地系统中文字体栈；数学和数值采用对齐良好的字体及 `tabular-nums`。运行时不请求在线字体。
- 采用 4/8px 间距系统，统一按钮高度、圆角、边框、阴影、标题等级和图例。
- 图标采用统一线性 SVG 风格，不能混搭 Emoji、不同笔画粗细和不明来源图标。
- 图形是视觉主角。使用克制的阴影与局部强调，不用满屏玻璃、霓虹、粒子和大面积紫蓝渐变制造“科技感”。
- 不做占满首屏却无法操作的大 Hero；首页进入实验的路径短、默认案例可立即运行。
- 六个模块共享产品语言，但主图具有各自的算法特征，不能六页都只是同一排统计卡片。
- 所有截图中的标题、单位、状态与数据都要真实，不出现 lorem ipsum、随机 KPI 或“准确率 99%”占位。

### 4.2 布局与响应式

桌面实验页建议为：可折叠导航 + 主实验画布 + 可收起的计算检查器。

顶部保留模块名称、数据/模型标识和主要操作；输入参数按任务分组；中间是主图；下方为轨迹、指标和实验记录。避免一页把所有公式全部摊开。

至少检查：1920×1080、1440×900、1366×768、768px 宽、390px 宽。

桌面优先。窄屏允许把复杂矩阵放入局部可滚动容器、把检查器改为抽屉，但输入、运行、结果与说明必须可访问。不得整页横向溢出，不要求手机同时显示完整大矩阵。

每个图表都要有标题、图例、坐标/维度解释、当前数据范围和重置视图入口。Tooltip 不遮挡主要控件，弹层不能超出视口。

### 4.3 动效与操作反馈

- 控件反馈可参考 120–220ms，教学步骤参考 300–700ms，并可调播放速度；这是产品设计参数，不是计算耗时。
- 让高亮、连线、数值变化对应真实计算步骤。禁止用动画进度冒充训练进度。
- 大数据更新不对每个点或矩阵单元执行复杂过渡。
- 支持 `prefers-reduced-motion`；关闭动效后所有功能和信息仍完整。
- 运行、暂停、取消、完成、失败、结果过期必须具有明确且一致的状态。
- 修改配置后标记旧结果“已过期”，不能继续当成新参数结果。
- 滑块同步数值输入与有效范围。训练类参数先预览、再显式运行；不得每移动一像素就重新训练。
- 长任务允许用户切换页面、观察日志和取消。进度未知时显示已处理数与状态，不编造百分比。
- 图形选择同时支持点击/键盘/数据表方式；不能只有鼠标悬浮能读取关键值。

普通文字对比度目标至少 4.5:1，大文字至少 3:1；必要的非文本控件视觉信息按 3:1 检查。[R05][R06] 点击目标以约 40–44px 为项目设计目标，但不把这一尺寸说成所有 WCAG 等级的统一硬规定。

## 5. 可视化技术：根据任务和规模选择载体

默认使用 D3 的比例尺、坐标轴、形状、缩放、刷选等能力，并结合原生 SVG / Canvas。D3 并不要求所有图形都成为 SVG 节点。[R01]

| 任务 | 建议表现形式 | 交互重点 |
|---|---|---|
| 小矩阵、卷积窗口、门控单元 | HTML/SVG | 精确单元选择、公式追踪、键盘访问 |
| 大词向量点云 | Canvas 绘点 + SVG 坐标/选区 | 搜索、缩放、框选、邻居高亮；只给选中点加标签 |
| 注意力矩阵 | 小规模 SVG/HTML，大规模 Canvas | 行列锁定、共享色域、差值视图、精确单元值 |
| RNN 时间展开 | SVG + 可视区域窗口化 | 时间步定位、状态轨迹、回退与比较 |
| 损失/梯度曲线 | SVG 或 Canvas | 多实验叠加、游标联动、原始点详情 |
| 分类错误样例与批量预测 | 虚拟化表格 + 图表联动 | 筛选、排序、混淆矩阵点选、跳转解释 |

不要同时引入 D3、ECharts、Chart.js、Plotly 来解决重复问题。确有必要增加库时，先给出已有能力无法满足的理由。

渲染规则：

- 计算全量数据，不等于一次把全部数据画成 DOM。默认避免创建上万个独立可交互 SVG 单元。
- 实施可配置的渲染阈值，依据基准测试调整，不将固定点数宣称为通用浏览器极限。
- 采用视区裁剪、矩阵分块、表格虚拟化、稀疏标签和曲线降采样；显示“总量/计算量/展示量”。
- 图形降采样只影响展示，不改变完整数据上的指标。曲线保留尖峰信息，并支持查阅和导出原始记录。
- 正负值采用以 0 为中心的发散色带；概率采用顺序色带；类别采用色盲相对友好的离散编码并配文字/形状。
- A/B 对照共享色域和坐标；改变显示范围应明确提示。
- 二维投影不等于原始距离。默认 PCA；后续引入 t-SNE 等算法时说明其解释限制，不用聚团漂亮程度评价训练好坏。[R04]
- 降维图的缩放/拖拽只是改变视图，不能暗中修改向量；跨训练快照比较需固定投影基底或明确展示对齐方式。维度或词表不兼容时不要强行套用同一投影；可改为并排展示并比较原空间的邻居/相似度指标。
- Canvas 必须配可访问的当前选择信息或数据表，不把全部数据意义封在画布里。
- 每个组件都具有更新、resize、selection 和 destroy 生命周期；离开页面清理监听、动画和任务订阅。

可借鉴 TensorFlow Playground 的参数与结果紧密联动，以及 Distill 的解释图文设计，但不得照搬页面和代码而不注明来源。[R02][R03]

## 6. 共享工程架构与数据契约

### 6.1 技术栈决策

优先沿用现有仓库。若尚无成熟应用框架，采用：

- HTML + CSS + 模块化 JavaScript，使用 JSDoc 定义关键类型；
- Vite 开发与构建工具；
- D3 + 原生 SVG/Canvas；
- Vitest 算法和状态测试；
- Playwright 浏览器交互、离线和视觉回归测试；
- ESLint / Prettier 做适度静态检查与格式约束。

界面漂亮不取决于引入 React/Vue。课程也不等于禁止框架；若仓库已有合理框架，不为本提示词强制推倒重写。

TensorFlow.js 等只作为经性能测试证实必要的可选加速实现，不作为看懂原理或离线启动的前提。不要求用户安装 GPU/CUDA，不把所有中间计算封进无法检查的黑盒。

### 6.2 职责分离

```text
app / modules       导航、模块页面、实验流程
components / viz    可复用控件、矩阵、热力图、曲线、检查器
core / algorithms   数学运算、NLP 算法、梯度、指标
workers / runtime   批量任务、暂停取消、调度、消息协议
data / artifacts    数据集、向量、模型、实验记录、导入导出
tests / scripts     验证、训练复现、构建、基准测试
```

算法层禁止操作 DOM。渲染层禁止自行生成“实验数据”。浏览器和 Node 训练脚本尽量共享相同算法核心。

可以按此骨架组织，并适配现有目录：

```text
src/
  app/
  modules/{embeddings,sequence,cnn,attention,comparison,optimization}/
  core/{math,random,metrics,optimizers}/
  algorithms/
  components/
  viz/
  workers/
  runtime/
  data/
  styles/
scripts/
tests/{unit,integration,e2e,bench}/
docs/
```

不要为了“可扩展”先造通用插件市场、任意计算图框架或大型状态管理基础设施。

### 6.3 统一数据对象

至少明确以下结构、校验规则与版本：

- `Dataset`：样本 ID、原文、Token、标签、划分、来源、许可、预处理版本。
- `ModelArtifact`：算法、结构、词表、权重、类别顺序、训练配置、来源和版本。
- `ExperimentConfig`：模块、模式、数据/模型引用、参数、随机种子、执行预算。
- `TraceStep`：步骤 ID、操作、输入输出引用、形状、必要数值、上游关联。
- `RunResult`：状态、结果、真实指标、警告、处理数量、计时、配置指纹。
- `Checkpoint`：可恢复的参数、优化器状态、随机数状态、数据位置和算法版本。

示意接口，不必机械照抄：

```js
runExperiment(config, { onProgress, signal, traceLevel });
predictBatch(model, samples, { onProgress, signal });
explainSample(model, sample, { traceLevel: "full" });
exportExperiment(record, { includeData, includeWeights });
```

`traceLevel` 至少区分 `none / summary / selected / full`。批量模式不保留每个样本的完整中间张量；选中样本时用相同权重重算解释。

所有界面结果都来自 `RunResult/TraceStep`。同一实验在图、表、说明和导出中必须一致。

### 6.4 状态与异步安全

采用清晰状态机，例如：

```text
idle → validating → running → paused → completed
                         ↘ cancelling → cancelled
                         ↘ failed
配置变化 → stale
```

任务消息包含 `runId` 与配置版本。新任务开始、取消或页面切换后，旧消息不得覆盖新结果。

区分“训练迭代步”“算法时间步”“动画播放步”。改变播放速度不能改变学习率、训练样本或最终数值。

原理模式保存适量完整状态；实验模式使用检查点和按需重算。回退必须恢复计算状态，不能只倒放动画。

## 7. 六个模块的具体实现与通过条件

### M01｜词向量：让语料、训练和向量空间连起来

**必须实现**

CBOW、Skip-gram 的负采样训练，以及基于非零共现记录的 GloVe 训练。显示每种算法适用的参数；不适用的控件隐藏或禁用并说明理由。

支持文本导入、可复现分词、词表、词频、窗口生成、训练进度、真实损失、向量查询、余弦相似度、Top-k 邻居、类比和二维投影。

**主交互**

中心词/上下文窗口联动；查看当前正负样本与向量更新；词频筛选、邻居连线、搜索定位；冻结 A 与 B 比较窗口或训练设置的影响。

**算法要求**

- CBOW 与 Skip-gram 的预测方向正确，区分输入与输出向量。
- 负采样使用明确的噪声分布及固定种子，可采用词频的 0.75 次幂；避免每步对全词表计算完整 Softmax。[R14]
- GloVe 使用稀疏共现统计及加权目标，展示共现值、预测值、损失与更新，不把全词表展开为无预算的 V×V 稠密数组。[R15]
- 相似度在原始向量上计算；零向量、OOV、重复词和不足词表都有可理解的处理。
- 类比检索说明规则并排除输入词；不保证小语料能得到经典语义类比。
- 降维坐标由真实向量计算。修改训练参数要重新训练或明确选择新快照，不得只移动散点伪装效果。
- 外部预训练向量必须有来源、语言、维度、许可和加载状态，与本地训练结果明确区分。

**通过条件**

窗口样例、负采样重复性、余弦和 GloVe 目标有独立测试；训练会真实更新参数；同一参考后端和配置可复现；大量词只减少标签/绘制密度，不减少声称参与检索的词表。

### M02｜序列模型：时间、记忆与梯度都能追踪

**必须实现**

RNN、LSTM、GRU 的真实单步前向；自定义输入；时间轴选择；隐状态、门值、细胞状态；暂停、回退、重置、状态比较。

**主交互**

时间展开图 + 当前单元结构 + 状态热力图。选择一个 Token 同步突出该步公式和矩阵；比较某个早期输入变化如何传到后续状态。

**算法要求**

- 页面公式与代码采用相同矩阵维度、门顺序和 GRU 变体，不混用 `reset-before/reset-after` 定义。
- 原理模式支持低维手算；实验模式支持更长序列，时间轴与状态表按视区展示。
- 修改第 t 步输入后，正确失效并重算后续状态。
- 梯度实验至少对 RNN 实现真实反向传播或明确推导的雅可比乘积，显示最终损失对早期状态的梯度范数，而不是把隐状态变小叫作梯度消失。[R18]
- LSTM/GRU 的梯度对比若展示，也必须实际计算；不得仅以结构复杂推断它们“没有梯度消失”。
- 提供经过测试的长序列案例；梯度裁剪展示裁剪前后值，不能将其宣称为消除梯度消失。
- M05 使用的 RNN 分类器必须复用本模块的前向定义与模型格式。

**通过条件**

三种结构均有可手算测试；连续运行与多次单步结果一致；回退再前进保持一致；参考小模型的梯度通过有限差分检查。

### M03｜Text-CNN：每一个分类结果都能追到卷积窗口

**必须实现**

文本 → Embedding → 多窗口卷积 → 激活 → max-over-time pooling → 拼接 → 分类得分/概率的真实流程。[R17]

支持多个窗口宽度、卷积核数量、权重查看和修改，以及参数变化前后比较。

**主交互**

高亮滑动窗口与对应特征图；点击激活展开逐项乘加；点击池化值反向定位来源窗口；分类条形图与数值表同步。

**算法要求**

- 卷积核覆盖 embedding 维度，并沿序列方向滑动，不能误做成图像的二维滑动卷积。
- 明确短文本、padding、有效窗口、ReLU 和池化规则；纯 padding 窗口不得悄悄主导分类。
- “教学参数”和“实际训练模型”分开标识。任意权重修改使旧评测失效。
- 结构参数改变时校验维度，重新初始化/训练或加载匹配配置。
- 提供可复现训练脚本和小模型快照；至少训练卷积层与分类层，不把完全固定随机特征模型伪装成完整训练的 Text-CNN。
- Dropout 若使用，训练与推理行为必须区分。

**通过条件**

手算卷积、激活、池化、类别顺序和梯度检查通过；M05 与本页对同样本、同模型的预测一致。

### M04｜注意力：权重不是魔法，能够逐格解释

**必须实现**

普通点积、可选缩放点积、加性注意力；源/目标输入；显式 Q/K/V 或可解释的向量映射；mask；权重和加权输出。

公式与实现应一致：[R16]

```text
点积：  score(i,j) = q_i · k_j
缩放：  score(i,j) = (q_i · k_j) / sqrt(d_k)
加性：  score(i,j) = v_a^T tanh(W_q q_i + W_k k_j + b)
权重：  A_i = softmax(mask(score_i))
输出：  O = A V
```

**主交互**

Token 对齐视图 + 热力图 + 当前行概率条 + 数值检查器；选择单元可查看分数到权重的变化；可比较 mask 前后、缩放前后、修改 Token 前后。

**算法要求**

- 改动 Token 后，根据明确的向量映射重新计算，不随机生成新权重。
- 分开标注“教学向量”和“有来源的训练向量”。没有训练好的翻译模型时，不声称注意力热图证明真实翻译对齐。
- Softmax 数值稳定。有效行权重和约为 1，屏蔽位置为 0。
- 整行全部屏蔽时拒绝该配置或返回带明确状态的无效行，不产生 NaN，也不伪造均匀分布。
- 因果 mask 只在有明确位置顺序含义的配置中使用，不机械套到所有源/目标组合。
- 大矩阵分块展示，保留全量计算和精确单元读取。
- 不把注意力权重直接宣传为模型决策的充分解释。

**通过条件**

点积与加性分别测试；mask、维度不匹配、极大分数、长输入均有测试；用户可从一个权重完整追溯其输入与公式。

### M05｜多模型对照：比较真实预测，而不是四张预设成绩单

**必须实现**

统一数据集、固定划分、统一标签顺序下的多项式朴素贝叶斯、线性 SVM、RNN 和 Text-CNN。

首个完整任务采用短文本二分类，界面中文；架构允许扩展多分类，但不能为增加任务数量牺牲基础二分类的正确性。

**主交互**

单样本四模型并排；批量预测表；指标比较；混淆矩阵筛选错误；按类别、长度、OOV、否定/转折等样例标签分析；点击样本送回同模型解释。

**算法与评测要求**

- NB 使用词计数与平滑，在对数空间计算。
- SVM 使用真正的 hinge 类目标与正则化，优先稀疏线性实现，不用关键词规则假扮 SVM。
- RNN/CNN 来自已验证的共享实现和可复现训练，不可固定概率或通过样本 ID 查答案。
- 显示预测标签、原始分数及其含义。SVM 决策分数不是概率；需要概率时用独立验证/校准数据拟合校准器并记录方法。[R19]
- 默认演示模型应带经验证的概率/校准说明；未校准模型明确显示“未校准分数”，不得把任意缩放结果显示为可靠置信度。
- 分类正确率、Precision、Recall、F1、Macro-F1、混淆矩阵由实际标签和预测计算，明确零分母规则。
- 无标签数据只能做预测与分布分析，不得显示准确率/F1。
- 预处理、词表与 TF-IDF 等拟合不使用测试集；早停、调参和校准不偷看测试结果。
- 四模型比较固定数据划分，记录不同特征和训练预算，不预设深度模型一定更好。
- 筛选后同时标明全量指标与当前子集指标，不能混淆分母。
- 耗时区分模型载入、预处理、计算和渲染，记录热身条件。

**通过条件**

四模型均能处理训练集外的新输入；批量与逐条结果一致；指标与人工统计一致；错误样本可追踪至同一模型版本；没有标签泄漏和预设成绩。

### M06｜损失与优化：把真实更新做成可操控实验

**必须实现**

从小型 Logistic/Softmax 分类器开始，实际执行前向、交叉熵、梯度、参数更新；控制学习率、迭代数、初始化、批大小；保存多组运行对照。

**主交互**

当前预测 → 每样本损失 → 聚合损失 → 梯度 → 更新后的参数。曲线上点击任意保存点，显示其配置和数值。

增加二维损失等高线与优化轨迹作为亮点：只在模型确实只有两个自由参数，或明确冻结其余参数的二维切片上绘制。不可把随意画出的山谷称为深层模型完整损失空间。

**算法要求**

- 曲线每个点来自真实迭代或明确周期的真实评估，不使用 `exp(-t)`、正弦波加噪声等伪造训练。
- 交叉熵采用稳定计算；显示 natural log 或其他底数约定。
- 对比学习率时固定数据、初值、样本顺序和评估口径。
- 训练批损失与固定评估集损失区分；不要把不同批次损失的波动直接解释成优化发散。
- 提供确实能产生慢收敛、正常收敛和大步长震荡/发散的验证案例；自由输入不保证出现同样图形。
- 发生非有限数值时中止、报告发生步和原因，不能偷偷裁剪显示值掩盖发散。
- 可接入 RNN/CNN 的真实训练日志，但保留完整来源与配置。

**通过条件**

交叉熵、梯度和单步更新有手算/有限差分测试；暂停恢复正确；预设学习率实验能够用日志重现，而不是看起来像预期曲线。

## 8. 数据能力与性能：给出目标、实测和上限，不夸大

### 8.1 数据输入与来源

至少支持 TXT 语料，以及 CSV / JSONL 分类样本；JSON 可用于实验配置和小型数据。

导入流程具有字段映射、编码/分隔符错误提示、预览、标签分布、长度分布、重复检查与确认。支持用户自带数据，而不是只能使用内置几条短句。

中文默认提供可复现的基础切分方式，例如空格预分词、字符级、版本固定的本地词典切分。说明不同方式的局限；不要用只按空格拆分的逻辑假装支持未分词中文。跨浏览器依赖系统分词时记录差异，严格复现优先使用固定实现或已保存 Token。

内置数据分三类：

- **教学金标准样例**：少量、可手算，验证算法。
- **学习/评测数据**：真实许可来源或明确标注的人工整理数据，有训练/验证/测试划分。
- **性能压力数据**：可以由生成脚本构造，只证明吞吐与稳定性，不用于声称真实语义泛化能力。

人工/大模型辅助生成数据要如实标注、审查并记录；重复扩写的句子不能包装为独立真实语料。相似模板按组划分，避免训练测试近重复泄漏。

数据获取需核验来源和许可；下载不成功就记录失败，不编造样本或标签来源。默认完全本地处理，不上传用户数据，不请求在线推理 API。

### 8.2 分档目标

以下是项目工程验收目标，不是已有跑分，也不是任意机器上同时拉满所有维度的保证。先记录参考机器 CPU、内存、操作系统、浏览器、构建模式，再运行固定基准。

| 场景 | 必测目标档 | 拓展压力档 |
|---|---|---|
| 分类数据导入与表格 | 10,000 条、总文件不超过 10 MiB，按需分页/虚拟化 | 50,000 条、50 MiB，分块解析并记录内存 |
| Word2Vec 训练 | 100,000 Token、词表≤5,000、维度32、窗口2、负样本5，先测单轮 | 1,000,000 Token、词表≤20,000、维度64，明确运行预算 |
| 词向量展示/查询 | 5,000 向量参与查询，Canvas 展示并稀疏标注 | 20,000 向量，限制标签与刷新频率 |
| 注意力计算 | 256×256 权重、d_k=32，分块查看且可读精确值 | 1,024×1,024，先估算内存并验证响应性 |
| 四模型批量推理 | 10,000 条、每条处理长度≤128 Token，小模型配置固定 | 更长文本/更多样本分别测，不同时无限放大 |
| RNN/CNN 浏览器训练 | 2,000 条、长度≤64、embedding/hidden等约32，批次执行 | 更大数据允许使用同源码 Node 离线训练，再导入模型 |
| 优化轨迹 | 5,000 次实际更新，曲线摘要与原始记录可对应 | 更长轨迹用检查点和分段导出 |

对 GloVe 单独测量非零共现条目数与预处理成本，不把 Word2Vec 的规模目标原封不动当成它已经通过的性能目标。

短文本超限时，让用户明确选择拒绝、截断或分段，并在结果显示原长度与处理长度。**不得静默截断后声称处理了全文。**

目标档未达成：先剖析瓶颈并优化；仍未通过则记录实测能力、原因和状态，不能改口声称已满足。拓展档不得阻塞核心六模块的最终可用版本。

### 8.3 计算与渲染优化

- 耗时训练、批量推理、共现统计、降维放入 Worker；主线程负责输入与绘图。[R07][R08]
- 使用 TypedArray、连续存储和缓冲区复用；矩阵维度与内存预算事先检查。
- 大块数据可用可转移 ArrayBuffer 降低消息复制成本。转移后原缓冲区会失去所有权，不能把仍在使用的模型权重随意 transfer。[R09]
- 模型尽量驻留 Worker，返回摘要/选中结果，不每步把整套权重传回 UI。
- Worker 内也要按批次让出执行权处理暂停/取消消息，不能一个同步长循环让取消按钮失效。
- 初始计算并发默认一个重任务，避免每个模块同时启动训练和占满 CPU；后续根据基准设置有限并发。
- 批量算法关闭完整 trace；只保存指定样本、检查点和统计。
- 使用稀疏词袋/共现，Word2Vec 负采样、批次推理、缓存预处理、合理早停和明确的最大步数。
- UI 曲线/进度更新通常节流到每秒约 5–10 次；不让每次梯度更新都引发 DOM 重绘。
- 主线程必要工作切片，优先检测 `scheduler.yield()`，提供兼容的定时任务回退；仅 `await Promise.resolve()` 不作为保证浏览器绘制的方案。[R10]
- CPU 参考计算保留可解释性。引入 GPU/WASM 加速必须证明确有收益、通过误差测试，并提供无加速回退。
- 使用 TensorFlow.js 时记录后端，正确释放张量，避免同步读回和张量泄漏；不要假定 GPU 对所有小矩阵都更快。[R20]
- 只有渲染可以近似/抽样；如算法本身近似、截断 BPTT 或只训练部分参数，也要明确说明，不能隐藏。

### 8.4 交互性能预算与记录

在已记录的参考机器、目标档和可见前台标签页下，作为优化目标：

- 普通控件与选择操作的输入到视觉反馈 p95 ≤100ms；
- 轻量参数反馈约≤200ms；重计算立即进入真实运行状态，不要求计算本身在200ms内完成；
- 暂停/取消确认目标≤500ms；
- 原理模式动画以接近60fps为目标，持续低于30fps需定位；
- 初始离线页面主操作区可用目标≤3秒，模型准备和大数据导入单独计时。

这些是待测试的项目预算，不是给用户机器的保证。记录多次运行的中位数与 p95，区分冷启动/热身、计算/渲染、前台/后台；后台节流结果不冒充前台性能。

内存 API 不可用时记录应用持有的数组/检查点估算和可获得的浏览器证据，不能捏造精确峰值。连续运行、取消、切页至少做10轮，检查资源回收和明显单调增长。

## 9. 离线交付：第一阶段就证明，不在最后补救

课程要求浏览器本地直接打开 HTML，不依赖后端。[A1][A2]

必须同时维护：

```text
开发方式：WSL → npm run dev → Windows 浏览器
交付方式：断网、不开 Vite → 双击 release/index.html
```

Vite 的默认应用构建面向静态托管；`base: "./"` 不能单独证明 `file://` 下模块、资源和 Worker 都能工作。浏览器对本地文件的跨来源访问有约束。[R11][R12]

交付实现要求：

1. 开发源码可以使用 ESM；离线构建将入口和依赖打包为可由普通 `<script>` 加载的浏览器脚本，例如 IIFE。按实际安装的 Vite/构建器版本验证配置，不照抄过时 API。
2. 不依赖动态 import、在线 CDN、运行时 fetch 本地 JSON、在线字体和远程模型下载。
3. 内置数据和小模型在构建时打包或以可本地加载的脚本资源提供；大文件通过用户主动选择 File 导入。
4. Worker 打包为自包含脚本；可以验证 Blob URL 创建经典 Worker 的方案，不能在 Blob 内留下无法解析的相对 import/importScripts。[R08]
5. 在实际 `file://` 测试中验证 Worker 初始化和消息交换。如果失败，使用经过测试的分块 CPU 回退并说明性能差异，不能要求关闭浏览器安全策略。
6. Hash 导航或等效本地路由；刷新、直接打开和中文/空格路径均测试。
7. 不把 Service Worker、跨源隔离、SharedArrayBuffer 或必须有服务器响应头的能力作为核心运行前提。
8. 存储适配层检测 IndexedDB/localStorage 能力；失败时保留内存会话和显式导出。`file://` 下 localStorage 行为不能假定跨浏览器一致。[R13]
9. JSON/CSV/Markdown 导出通过本地下载完成。用户不需要安装 Node 才能运行交付网页。
10. 标准构建不自动打包个人路径、隐私文件、API Key 或无许可大语料。

建议提供 `npm run build:offline` 和 `npm run test:offline`。具体脚本由你实现并实际运行，不要只把不存在的命令写进 README。

同时约定可重复执行的 `npm run dev`、`npm run test:run`、`npm run test:e2e` 和 `npm run bench`；`test:run` 必须单次运行后退出，不能让 Agent 卡在测试监听模式。尚未实现的脚本不可在交付说明中标为可用。

`test:offline` 应在关闭开发服务器后导航到真实 `file://` 入口，拒绝意外 HTTP/HTTPS 请求，运行核心交互并检查控制台。单纯 mock 网络响应不算离线通过。

## 10. 安全、错误处理与数值可信度

- 输入文本、标签、导入说明全部当作数据处理，不拼入可执行 HTML，不使用 `eval` 执行用户内容。
- 文件解析校验大小、字段、深度、样本数、维度与有限数值；错误指出行号或字段，并允许修正/取消。
- CSV 正确处理转义和引号；导出会被表格软件解释的字段时防范公式注入。
- 数学核心实现稳定 Softmax、log-sum-exp、交叉熵、sigmoid；每个算法清楚处理空数组、零向量、mask、溢出和除零。
- 随机初始化、抽样和 shuffle 来自可播种随机数生成器。随机性可用于算法，不能替代算法。
- 缓存以数据、参数和模型版本为键；禁止新配置读取旧结果而不标注。
- 外部模型/实验导入进行 schema 和形状校验，不信任文件中的模型名称和声明成绩。
- 页面异常不能静默吞掉。给出可理解提示、恢复入口和诊断记录，保留用户输入。
- 不设“所有模型至少90%准确率”等诱导伪造的硬指标。性能、准确率和完成率都只能来自实际实验。

## 11. 测试体系与视觉验收

### 11.1 数学单元测试

核心参考实现使用可手算的确定性样例，例如：

```text
softmax([1,2,3]) ≈ [0.09003057, 0.24472847, 0.66524096]
softmax([1000,1001,1002]) 应与上例接近且没有溢出
二分类真类概率0.8时，natural-log交叉熵 ≈ 0.22314355
被屏蔽位置的注意力权重为0，有效行权重和约为1
```

覆盖：矩阵形状、余弦、窗口、卷积、池化、三种序列单元、注意力两种打分、损失、优化更新、NB、SVM、分类指标。

小模型梯度用独立有限差分检查；不要用同一段实现计算“预期值”再和自己比较。

参考双精度、Float32 与可选加速后端使用合理的绝对/相对容差，先制定依据再看结果；不能为了过测试任意放宽误差。ReLU/max 的不可导点需避开或明确采用约定，不把所有差异都判作实现错误。

### 11.2 集成与交互测试

每模块至少覆盖：

- 默认案例完整运行；
- 自定义输入和至少一个有效参数改变；
- 关键中间值与图/表联动；
- 重置、异常输入、取消或回退等适用控制；
- A/B 比较与实验导出；
- 依赖模型/数据变化后的失效处理。

此外覆盖数据导入、四模型批处理、跨模块送样、旧任务消息、模型兼容性校验、实验导入重放。

Playwright 使用角色/文本定位与适当的等待断言，不靠大量固定 sleep 掩盖时序问题。[R21]

### 11.3 视觉检查不能省略

为首页、六个模块、A/B对照、导入界面、空/错/加载状态，以及关键窄屏尺寸生成截图。

截图后必须实际查看并修复：文字裁切、矩阵错位、图例与图不一致、颜色难辨、按钮遮挡、密度失衡、巨大留白、弹层出界和手机整页溢出。

固定种子、字体环境和动画状态再做截图回归。**自动截图不等于视觉验收；没有看过就不能说界面美观。**

### 11.4 完成判定

为每条需求建立：需求 ID、来源、实现文件、测试用例、证据、状态。

状态只使用：未开始 / 进行中 / 已实现待验收 / 已验收 / 阻塞。不能只按卡片或页面数量计算完成度。

最终必须同时满足：

- 六个模块及第2.1节中的核心要求均有真实实现和验证；
- 四项核心创新有可重复操作的完整链路；
- 交互和截图通过检查，核心操作没有已知阻断；
- 算法测试、批量测试和离线测试结果有证据；
- 达到或明确披露未达到的数据档位与性能预算；
- 没有未说明的假数据、假曲线、随机分数或外部依赖；
- 报告材料、模型/数据来源和运行说明齐备。

### 阶段 F：真实性、性能、视觉与交付审计

运行固定测试、基准、断网回归和截图检查；修复问题；整理来源和报告证据。不得为追求全部打勾而删除测试或把失败数据隐藏。
